# 交付契约

录制前先确认本次交付契约，是 CHEK EGO Miner 的基本规则。这个项目由擎控科技团队带来，手机端叫 CHEK，桌面端叫擎控Miker。

如果你只是普通采集者，可以把它理解成一句话：开始前先看清楚“这一次到底会保存什么”，确认后就按这份内容完成采集。

## 它是什么

交付契约就是“这一次到底要保存什么”。

它不是固定写死的三相机逻辑，也不是静态的标准档和增强档开关。

在普通用户能看到的界面里，它应该被解释成“本次将保存 / 本次不会保存 / 本次不能保存”，让采集者知道自己正在提交什么。

## 它怎么生成

本次契约由四部分共同决定：

1. 当前插入并可识别的真实硬件能力
2. 用户这一次选择参与的设备和角色
3. 用户这一次明确确认要保存的内容
4. 预检结果

## 它什么时候冻结

用户点开始录制之前，要先冻结这一次的契约。

冻结后，这一段录制、后续验收、恢复和上传都按同一个契约走。

## 冻结后不能做什么

- 新插入的设备不会自动加入本次采集
- 如果设备少了或任务要求变了，需要重新检查和确认
- 如果确认要保存的内容没有采到，需要按任务规则重录或标记失败

如果契约确认后设备变化了，要重新确认。

## 用户可以理解的页面文案

### 本次将保存

- 彩色视频
- 深度图
- 红外图
- IMU
- 其他本次明确勾选的内容

### 本次不会保存

- 这次没勾选但设备支持的内容
- 这次任务不要求的内容

### 本次不能保存

- 设备不支持的内容
- 标定不完整的内容
- 预检没通过的内容
- 存储空间不足时无法完成的内容

## 一句话原则

如果用户确认了某个必须保存的内容，但最终没拿到，那一段录制就应该诚实地失败，而不是静默通过。

## 和收益有什么关系

如果任务包含奖励或结算，最终是否通过审核通常会看任务规则和本次交付内容。不要只因为录到了一段视频就默认通过；也不要在缺少必需内容时把失败片段当成完整数据提交。
